# 恢复方法与边界

公开仓库不包含这台设备的原始设置备份、签名密钥或配对密钥。先生成自己的备份，不能把别人的快照当成自己的恢复包。

## 音量

当前方案是“专用键位文件 + 无障碍服务”一组。恢复顺序：

1. 确认仍能使用 ADB 或其他控制方式。
2. 如原来有 IDC，恢复原 IDC；否则移除本次新增的专用 IDC。
3. 移除本次新增的自定义 KL，保留 `/vendor` 中原始 KL。
4. 重启或重新加载输入设备，确认原厂音量键已恢复。
5. 最后再停用/卸载工具。

只卸载 APK 会让 F11/F12 无人处理，造成“音量键坏了”的假象。

## Home 和后台

`HomeConfig undo` 清除对第三方桌面写入的持久偏好；同时关闭自写工具的开机桌面补充切换。不要误清普通用户设置或整个 PackageManager 数据库。

本机厂商后台总开关原值为 true，恢复时可回到原值；没有要求其他设备一律设成 true。独立名单和系统正常回收是另一层机制。

## 语音

工具的独立语音开关关闭后，新增命令不再由补丁处理，后台不再重注入。若要移除当前内存补丁，关闭开关后重启原语音进程；原助手 APK 从未被替换。

更新补丁前先关闭自动加载，备份旧脚本，更新 root 所有文件，再重启助手、重新开启加载。不要把两个版本的 hook 堆叠注入同一个进程。

## 屏幕联动

电脑程序支持 `--stop` 停止当前后台，`--monitor-only` 按本地配置恢复电脑显示器。

完整停用应同时移除当前用户 Run 项 `CodexProjectorDisplayRouter`，否则下次登录又会启动。Android 端可以独立暂停联动，电脑保留当前布局。

配对配置必须自己生成并保存到私有目录，不提交到公开仓库。若完全卸载“遥控优化”，电脑侧也应停止后台，避免不断等待已不存在的状态服务。

## 性能调整

本次保留窗口动画和过渡动画 0.5；原值均为 1.0。全局动画时长键原先不存在，试过后已经删除以恢复默认。

ART 编译产物可按记录的旧过滤器请求重新生成，不改用户业务数据；Android 可能按应用属性调整实际过滤器，必须读回确认，不能只相信 `Success`。

## 哪些恢复没做过完整演练

最终全部恢复脚本有语法与依赖检查，但没有为了证明可恢复而把正常设备全部拆回去。服务停止/重启、语音独立开关、模拟无障碍配置丢失恢复等有实测，不能把这些局部验证扩大成“任何情况都能救砖”。

没有完整固件恢复镜像，没有证明跨固件版本兼容，也没有承诺恢复出厂或 OTA 后配置仍保留。
