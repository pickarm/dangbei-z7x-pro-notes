# 验证状态

记录整理至 2026-11-24。各项按对应测试的观察结果记录。

## 确认成功

- 音量：真实范围 0～100，短按每次 1，长按连续调整，松开停止；实体遥控器确认。
- 内置喇叭：0 保留静音，1～100 使用 −75 dB 到 0 dB 的单调曲线；用户确认平稳、低档合适。两次完整重启后重新载入，分别恢复 29 和 30。
- Home：两类 HOME intent 均登记持久默认项，仅停用原厂首页组件；用户确认重启后直接进入第三方当贝桌面。
- 后台：厂商包级 adj 100 只用于 `local.tvkeys`，重启读到该服务的 adj 100、调度组 2。另有独立防护，只拦截 Etna 对遥控优化和第三方当贝桌面的强停。
- 任务清理：移除工具界面任务后服务继续运行；模拟自身无障碍启用项丢失，约 3～11 秒恢复。
- 光源：正常 1～10 档，1→10→1 保持 30 秒的实际光强变化由实体观察确认。
- 语音：调光源、打开应用、有反馈，之后悬浮面板和头像自动消失；用户确认。
- 语音持久化：重启和原助手进程重启后，新 PID、补丁版本、启动标识均匹配；临时诊断入口停止。
- 屏幕：改线前断开 ADB 后，系统与 HDMI 1 两种状态成功往返；后续用户也确认黑屏修正后的原端口往返正常。
- HDMI 2：源编号 2 已在实际信号中读回。用户确认选中该源时切到投影仪单屏，回系统后恢复外接显示器单屏。
- 显示模式：修复回到外接显示器时的 60 Hz 回退。用户确认修复后 HDMI 2 往返正常，Windows 读回 G27P6M 2560×1440、279.961 Hz。
- 屏幕后台：已改为 Windows 计划任务；结束进程后观察到定时补启动并重新发现投影仪。

## 没有完成或不能据此推断

- Apple TV 正片仍无法播放，没有许可证错误码证明唯一根因。
- Play 商店可进入初始登录界面，Google 登录和设备认证未验证。
- v5 的新增语音信号源命令只完成代码加载，没有完成新的实体语音测试；该任务随后停止。
- 计划任务的 Windows 登录触发已配置，迁移后未单独通过重新登录验证。
- 厂商重启流程未触发试验的 `ACTION_SHUTDOWN` 接收器，已删除该方案。已验证的是曲线加载时静音。
- 微信输入法的 32 位测试包缺失核心引擎，已卸载；原搜狗电视输入法保留。
- 没有主动更改 DHCP 地址做一次真实换 IP 测试；验证的是无固定 IP 配置、广播发现及重启电脑后台后的重新发现。
- 没有完整执行最终“全部恢复”流程；恢复脚本有语法与依赖检查，服务停止/启动另有实测。
- 预编译后没有测得显著启动提速，也没有证明桌面 FPS 有提升。
- 发现配置和辅助函数，不等于每个厂商限制都已实测触发。
