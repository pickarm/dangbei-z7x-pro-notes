# 当贝 Z7X PRO 折腾总结

整理至 **2026-11-24**。设备系统识别为 D7XPG，运行 Android 13、v6.11.3、32 位固件。本文汇总当前做法和实际验收，按时间查过程见[时间线](08-timeline.md)。

## 应用、电脑代理与输入法

Google 框架和 Play 商店已安装，商店能进入初始登录界面。停止使用投影仪端 Clash 后，改用电脑提供的局域网 HTTP 代理，可从投影桌面独立开关。一次 Google 登录失败追到电脑端加速工具的 hosts 和 TLS 干预，关闭后域名探测恢复。账户登录和设备认证仍未验证。

Apple TV 补桌面入口后能启动，正片仍无法播放。设备报告 Widevine L3，日志有 L1 信任和密钥盒异常，Apple TV 的具体许可证错误码未取得。微信输入法在这台 32 位设备上缺少适配的核心引擎，测试包崩溃。结束测试后卸载该包，继续使用原搜狗电视输入法。[应用、代理及播放记录](06-apps-proxy-drm.md)

## 遥控优化、喇叭和桌面

这台设备的系统媒体音量范围为 0～100，原厂音量条显示更粗，喇叭增益也另有映射。通过遥控器专用键位和无障碍服务，让短按每次变 1，长按连续变化，松开停止。处理了前台服务被降到低优先级后集中补执行按键的问题，应用会丢弃过期事件。包级规则只给 `local.tvkeys` 设 adj 100，另一道防护拦截 Etna 对遥控工具和第三方当贝桌面的特定强停。

按键逐格后，内置喇叭仍有低档过响的问题。实测原 HAL 在 5→6 档时增益反向，延时两秒半后的读数仍一致。换成 1～100 对应 −75 dB 到 0 dB 的单调曲线，0 保留静音。用户确认调节平稳、低档合适。随后正式启用开机加载，按 `boot_id` 和 HAL PID 核对加载状态，两次完整重启分别恢复 29 和 30。加载先静音，确认曲线 ready 且 SELinux 策略恢复后再恢复档位。失效的 `ACTION_SHUTDOWN` 静音试验已撤回，最终遥控优化为 **2.6.3 / versionCode 13**。

Home 登记两类持久默认项，并保留开机补充切换。只停用原厂首页 SplashActivity，继续启用原厂服务、provider 与系统备用 Home。用户确认重启后直接进入第三方当贝桌面。[遥控、曲线和 Home 记录](02-remote-home-background.md)

## 语音和性能

复用原助手的识别与播报，实机确认语音调光源 1～10、打开已安装应用，以及反馈后收起面板和头像。整机重启、助手进程重启后的自动加载做过验证。v5 的语音切源已加载，实体语音验证未完成。小范围预编译和动画调整留下了启动数据，未测得明显提速或可靠的桌面 FPS 改善。[语音记录](03-voice.md) · [性能记录](05-performance-and-restrictions.md)

## 电脑和投影仪屏幕联动

Windows 通过局域网配对读取投影仪真实信号源。只有 `playing=1` 且来源等于校准后的 `computerSource` 才切到投影仪。按 Home 回系统后，电脑回外接显示器。状态未知或超时也优先用外接显示器。自动切屏只用临时 Windows 布局。

早期联动在投影仪重启后遇到外接显示器黑屏，拔 HDMI 恢复。修复了只凭源编号切屏的问题，黑屏瞬间的具体触发原因缺少日志。程序迁到 `C:\ProgramData\CodexProjectorDisplayRouter`，由 Windows 计划任务负责登录启动、失败重试和每五分钟补启动。实际观察到进程终止后被重新拉起，用户也确认过原 HDMI 1 与系统往返。

11 月 24 日改接 HDMI 2，插线时再次出现外接显示器黑屏。保持 HDMI 接线、重新保存仅显示器基线后，用户确认画面恢复。按本机 SDK 将 Windows 的电脑源编号改为 2 并重载任务。首次往返时用户发现返回显示器后刷新率降到 60 Hz。新版按屏幕保存并恢复可信单屏模式，用户复测 HDMI 2 往返正常，Windows 读回外接显示器 2560×1440、约 280 Hz。[屏幕联动及最新状态](04-display-router.md)
