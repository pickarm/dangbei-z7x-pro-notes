# 语音增强：让“好”变成实际执行

需要控制的是投影灯的**光源亮度**，正常档位 1～10，不是图像亮度、对比度或工程校准参数。

## 先找到真正的执行接口

设置中的光源逻辑使用 `GmDisplayManager.getDlpLumensLevel()` / `setDlpLumensLevel(byte)`。在本固件中，对应服务为：

```text
xgimi.hardware.gmpf.IDisplayManager/default
事务 7：读取光源档位
事务 6：写入正常档位
```

经过 1→2→1、1→10→1 的真实投影测试，最后 10 档保持 30 秒后恢复，观察确认光强确实变化。没有修改校准表、RGB、温控或保护逻辑。

## 复用原助手的识别和播报

原助手是 `com.dangbei.lerad.rocky`，使用自己的录音、识别、播报链路。没有发现可直接复用的标准 Android RecognitionService。

外部接收识别广播的尝试没有成功：相关广播显式发给原厂桌面，普通外部接收器拿不到预期文字。最终在原助手进程中加载运行时补丁，拦截识别完成和 AI 输入入口，仅处理明确的新增命令；其他命令继续交回原逻辑。

已确认的命令包括：

```text
光源亮度调到三
亮度设为 10
调亮一点 / 调暗一点
最高亮度 / 最低亮度
打开 Apple TV
打开某个已安装应用
```

数字严格限制 1～10。图像亮度、百分比和取消等情况有单独处理。应用按实际安装列表匹配，名称不唯一则提示完整名称，不随机选一个，也不执行任意 shell 字符串。

## 自动退出语音面板

只调用 `removeView(0)` 会缩成悬浮头像，仍需按返回。最终使用原面板的强制退出标记，结合隐藏 UI 与返回流程，在播报结束后关闭；另有超时兜底，并避免把下一次新语音会话误关闭。面板和头像都消失后由实体操作确认。

## 持久化方式

不是修改原助手 APK，也不是刷机。自写后台在开机后和约每分钟检查一次 PID、启动标识、补丁版本；只有需要时短时调用已验证的 root 入口注入，加载后关闭诊断入口。

使用 Frida 17.26.0 android-arm 和 frida-java-bridge 7.0.13。本机 ARMv7 遇到桥接的指令兼容回归，参考[上游问题 364](https://github.com/frida-packages/frida-java-bridge/issues/364)处理后才正常。注入工具会临时调整内存 SELinux 策略，所以加载前保存、加载后恢复，并校验策略摘要一致；没有保留新的永久策略。

v4 的光源、打开应用、反馈、自动关闭和跨进程恢复已有实机确认。v5 新增了语音切换 HDMI 的解析与执行代码，已加载，但随后停止了这项任务，没有完成新的实体语音确认。仓库保留 v5 源码，**不把它写成已验证功能**。

本机原本就是 Permissive。上述方法不说明应该把其他设备设为 Permissive，也不说明 OTA 后仍能继续使用。原识别和播报仍依赖厂商服务及联网状态。
