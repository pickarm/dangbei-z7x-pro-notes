# 时间线与踩坑

日期按本次会话和现场记录整理，保留状态变化，不把早期失败删除后伪装成一次成功。

## 2026-11-03～11-04：先装应用

- 开启并连接 ADB，安装 Google 组件、Play 商店、Apple TV。
- Apple TV 安装不等于有桌面入口，补启动桥后能打开。
- 电脑代理做成独立桌面开关，系统代理在界面退出后仍保持。
- Apple TV 仍无法播放，临时开代理无效。查到 Widevine L3、L1 信任 / Keybox 异常，但没有确认 Apple TV 唯一失败原因。

## 2026-11-06：音量、Home、后台

- 普通 `adb root` 不可用；找到固件已有的短时 root 诊断入口，身份和权限验证通过。
- 最初误把音量条的粗档位当成真实上限，后来发现底层已经是 0～100，重点应是按键步长与原厂显示。
- 直接额外拦截普通音量键会叠加处理；资源覆盖尝试最终撤销。
- 改专用遥控器 KL/IDC，只替换两个音量键，再由自写服务每次调整 1。
- 普通默认桌面设置仍出现厂商选择器，改为登记两类持久 HOME intent。
- 关闭额外短时后台强停开关，但保留正常 Android 回收。
- 后来出现任务清理后服务停止、无障碍配置被清空，音量键失效。升级工具，补前台服务、自恢复和开机补充桌面切换，实际重启后实体确认正常。

## 2026-11-06：语音

- 先确认需求是光源亮度，再找原生控制接口，实测到 10 档保持 30 秒。
- 外部识别广播接收路线失败，换为复用原助手进程内识别结果。
- Frida / Java 桥在 ARMv7 遇到指令兼容问题，处理对应上游回归后才正常。
- 语音调光源、打开应用成功；只隐藏面板还会留下头像，修到完整退出后用户确认。
- 获得明确持久化授权后安装自动加载；验证整机重启、助手进程重启后的恢复。

## 2026-11-06～11-07：性能和信号源

- Windows 一开始按“投影仪是否在线”保存仅投影仪布局，后来发现没有覆盖“投影仪在线但仍在系统”的情况。
- 投影仪原生 HDMI 自动切换开关原为开启，已关闭；默认开机源设为系统。
- 新增语音切 HDMI 的 v5 代码已加载，但随后停止继续做这项测试，因此没有算验证成功。
- 流畅度体检发现存储充足、内存压力不高；当贝桌面带 DEBUGGABLE，不能直接用 speed 完整预编译。
- BT、网易预编译读回成功，窗口动画调短；一组与编译重叠的数据作废。有效测量没有明显提速，完整记录保留。

## 2026-11-07：按实际信号源联动屏幕

- 需求明确为：系统只亮显示器，电脑 HDMI 只亮投影仪，内屏关闭。
- 因投影仪没有固定 IP，放弃长期依赖固定 ADB 地址的后台方案。
- 更新“遥控优化”2.3，增加只读局域网配对状态应答；电脑通过广播发现设备。
- 主动断开 ADB 后，用实体遥控器在系统与 HDMI 1 往返，确认正常。
- 电脑程序部署到用户程序目录、配置登录自启，重启后台后自动重新发现。没有把这一步写成完成了两端整机重启测试。

## 最有用的经验

“能安装”“有入口”“能启动”“能播放”是四个不同结果。`Success`、状态字段、实体表现也不是一回事。默认 Home 正确不能证明开机一定停在第三方桌面；HDMI 在线更不能证明用户正在看电脑输入。
